# v0.5 M4 — conservative reach and held capture

The new reach advisory and short held-intent buffer are independent opt-in flags, both OFF by default. They reuse the existing predictor, finite hand actuator and material anchor. No change to reach, force, momentum initialization or grip integrity was justified. Actual geometry, transit contact and retention remain the sole physical authority.

`reach_assessment.gd` adds a sampled anatomical-window interval, finite-arrival information, future relative point velocity and confidence. It keeps the predictor's.20s horizon (bounded.10–.25), with samples no coarser than1/120s. Interval exit is the last inside sample, not the first outside sample. The advisory explicitly distinguishes a geometric window from a predicted catch: `PREDICTED CATCH WINDOW` requires a finite predicted arrival; otherwise arrival remains unknown. A valid current request is not rejected when the hand requires longer than the horizon.

Future point motion uses actual COM, velocity, spin, gravity and last known arm-force estimate. Constraints, contact impulses and future control changes are unmodelled. Dynamic/rotating supports, body rotation, ground contact and supported dynamics reduce confidence. Static conveyor velocity affects contact velocity without falsely translating its collider. Window intervals describe predicted anatomy, not certified future collision clearance.

An optional `UNSAFE CATCH (estimate)` warns when outward radial energy at the effective point mass exceeds an optimistic360N-or-grip-capacity stopping-work upper bound over remaining extension. It includes rotational inverse mass and actual automatic/custom COM. This is an instantaneous one-axis estimate; engagement blending, other loads, changing leverage and contacts reduce real capacity. It never authorizes or denies a catch. An adverse fixture measures4.427kg effective mass,9.961J outward energy versus8.497J upper-bound stopping work; the actual request remains physically admissible and independently evaluated.

The buffer reuses `GripIntentBuffer`, remembering one selected material-local point for one held button. Default duration is.12s; the explicit UI range is.10–.15s. It accepts only the existing near-future admission conditions and still requires finite hand travel and actual contact. Release, UI, focus loss, disable and reset cancel pending intent. There is no target-following cursor, automatic retry or post-release attachment. The legacy predictive toggle remains available; advisory alone never enables it, and the new buffer is scoped to independent aim.

Main integration stores a deep-copied assessment before the intentional press, separately from hover advice. Per-attempt JSONL and traces include that frozen assessment, flags, duration, confidence and observed outcome. Pointer motion cannot rewrite the attempted target or its earlier forecast. Non-hand motion events carry no fabricated hand assessment. The free-hand marker also now ignores the already attached hand's reach; both-held shows no available hand.

Validation:

- `test_reach_assessment`:39 checks per frequency. Real fixed/translating/rotating supports, COM/inverse point mass, future finite-contact relative velocity, confidence, geometry-only window, current valid long hand path, outward-load warning, pointer/camera invariance and no actuation. A free rotating/translating no-contact100ms fixture agrees with extrapolated material point to about1.5e-8m; this is deliberately not a constrained-beam prediction guarantee.
- `test_transfer_capture`:25 checks per frequency. Advisory OFF/ON gives exactly identical body/contact trajectories. Same early press is rejected with buffer OFF and catches with buffer ON after real finite travel. Original point and immutable assessment survive pointer motion; release/UI/focus/disable cancel. Profile scope and legacy toggle interactions pass.
- Native Godot MCP Pro comparison and final full regression are recorded in the overall report and `v05_final/`; automated input is labelled separately from interactive observations.

Both runners pass at60/120Hz. The first advisory-equivalence harness started its first app outside the physics-frame boundary and observed one-tick sampling misalignment; aligning every setup to `physics_frame` restored exact equality without modifying production physics. This was a harness timing error, not an actuator fix.
