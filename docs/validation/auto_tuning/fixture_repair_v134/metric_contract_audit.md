# Metric and measurement audit

The original R3 `metrics.py` formulas and their typed status enums remain unchanged. v134 has no score, optimizer reward, statistical qualification or default promotion. Each CSV metric includes value or explicit JSON null, unit, status, reason, authorized window, scenario/fixture revision, source/tape hash, Hz and mode.

Runtime validity, a certified onset, a completed task window, a measured objective and same-Hz H/R equality are separate decisions. `measurement_valid` is applied to the adaptive source **and both** fixed replay legs; an identical pair of failed windows cannot become feasible. A progress task requires actual directed success over its complete authorized interval. Stop requires both confirmed 3D stop path and settling. Diagnostic Foot/Stop never become eligible for ranking.

Latency is not required to be MEASURED when useful directed movement already existed before onset. Lateral120 illustrates this: positive complete-window progression coexists with `PRECONDITION_NOT_MET / ALREADY_MOVING_BEFORE_ONSET / null` latency. This is not zero latency or an improvement claim. Accepted input and the actual sustained response timestamps remain available.

R3 and v134 prerequisite files distinguish quiet preparation from accepted onset. The expanded diagnostic view exposes all false clauses, actual ground force/torque, native-support state, hand load/material continuity, foot compression, relative-speed availability, full spin, prior same-anchor dwell and accepted command/speed. Stop's accepted speed0.15..0.5m/s is separate from quiet speed≤0.1m/s. Authoritative onset/phase/interruption is joined from the actual driver certificate and independent metric result, rather than guessed from a quiet funnel. Missing support velocity cannot become a valid relative-motion predicate.

Interrupted captures retain their raw authorized prefix in the original trace. Official whole-window progress/efficiency remains null with its reason, rather than using that prefix as a score. Step's no-onset metrics remain `PRECONDITION_NOT_MET/null`, even though intermittent physical foot load occurred during preparation. Conservative clearance rejection is distinguished from native collision truth; contact reporting limit0 remains UNKNOWN.

Confirmed-stop path integrates COM motion in3D up to confirmation of sustained low-energy support. Settling reports the beginning of that sustained interval after its confirmation is observed. Neither the entire five-second path nor the final signed drift replaces stopping distance. No exact trajectory comparison is made across different physics frequencies.

The supplemental `foot_load_work_diagnostics.json` preserves preparation compression/load and a discrete static-support point-work proxy. Its formula is the existing physics-test convention, F·(vCOM+ω×lever)Δt, with published applied foot force at the actual contact point. It is explicitly diagnostic and not a new movement metric or solver energy assertion. Failed/interrupted official windows retain null work; raw preparation work is separately named and cannot establish a valid Step or useful B1 benefit. Unknown native calf/lip contact is not assigned zero effect.

FR0 uses a separate named endpoint API representation contract with original measured bit witnesses. It does not round general physical samples or change any query. New dispatch IDs require exact session/tick/hand/ordinal, chronological one-to-one correspondence, real ordered ray results and winning material hit. Original scalar/binary evidence and the legacy comparator are retained. Both strict pairing and the independent reviews can reject a mismatch regardless of task completion.
