## Typed cursor contract

Only the specifically named cursor inputs have native Vector2 float32 representation semantics: `canonical_input.requested/effective.aim_position_viewport_px` is the unmodified parsed JSON scalar pair; `canonical_input.effective_aim_px` is the actual native API vector published at full precision. The audit preserves each original value, Python parsed type, binary64 bits, native binary32 bits, canonical decimal and provenance. It validates finite non-boolean numeric pairs. Actual API components must be exact promoted float32 values, not truncated legacy decimal approximations. No ray, normal, material point, force, COM or other physical sample is canonicalized.

For a valid aim, each raw scalar converted through native binary32 must agree exactly with the corresponding actual API coordinate. For an invalid aim, raw coordinates are not interpreted as an aiming command and are not recentered; the recorded actual pointer remains recorded. Across modes, actual native cursor bits and validity are compared by matching physical tick. Raw requested/effective frame payloads remain independently compared without changing their bytes or values. Missing data returns `INVALID_SCHEMA`; incoherent raw/native semantics return `TYPE_REPRESENTATION_MISMATCH`; a genuine corresponding typed cursor inequality is a mismatch. None can become `STRICT_MATCH` by an epsilon.

The legacy comparator implementation and returned `legacy_layers` output are retained unchanged. A new adjacent `legacy_interpretation` explains a self-comparison only when the typed audit demonstrates equivalent raw/native coordinates and the sole legacy mismatch is the cursor. An unexplained legacy discrepancy cannot receive a strict verdict. This is not a general JSON-losslessness claim.

An offline regression using the preserved R2 raw sample reproduces its two operands: raw Y `480.534973144531` / binary64 `fcffff3f8f087e40`; actual Vector2 Y `480.53497314453125` / binary64 `000000408f087e40`. They produce the same binary32 coordinate. R2's recorded H/R diagnostic pair still recomputes as strict for its measured channels, with the old cursor mismatch and the explicit representation interpretation both retained. That is historical validation of comparator behavior, not an R3 replay pass.

## PC2 channels, phases and localization

Comparison requires consecutive POST rows at the same 60 or 120 Hz, declared delta/timestamps, the original JSON input-frame fields, actual body/contact/force fields and the existing applied-input/ground telemetry. Recorded contact events are now included in the CONTACT layer, preserving their episode tick and pre/post phase. Their process-global `run_tick` is metadata: it includes startup callbacks before a world and is excluded from cross-process equality. The raw records retain it. Clock startup, its transients and the world-creation boundary must independently pass the runner's admission certificate; this exclusion does not permit dropping gameplay ticks.

INPUT compares requested/effective/accepted/applied commands, camera commands, button edges and virtual focus/pause policy. Hardware focus is context; a stopped/suspended or paused replay is rejected by admission/runtime guards, not filled with synthetic input. PICK retains actual camera/ray/offset/hit/material observations and binary sidecars. CONTACT retains real hand states, anchor chains, actual foot/native support, rest lengths, forces, reactions and contact events. PHYSICS retains COM/pose/v/omega, budgets, solver/ground ownership and planner channels. TASK retains real catch completion, source release, destination retention and task/onset summary. Empty native-contact buffers do not establish absence of support; configured reporting limitations and real ground/B1 contributions remain explicit.

The first difference is selected by earliest physical tick, with layer order only breaking a same-tick tie. An earlier physical difference is no longer hidden by a later INPUT difference merely because INPUT appears first in a list. `first_actual_physics_divergence` and a strictly later `first_later_physics_divergence` are retained separately. A point-of-call difference participates in this ordering. Missing schema/identity produces a typed invalid comparison rather than a false equality or a failed-climb score.
