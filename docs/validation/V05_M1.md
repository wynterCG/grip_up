## Gate and outcome

remaining finite hand time, relative velocity and load. It cannot inherit the
previous attempt's manual-release reason. Instrumentation does not select a
route, change an anchor or alter any physical command. M0 baseline is c2a6a2b;

## Changed files / algorithm

- `transfer_diagnostics.gd`: bounded256-event journal, monotonically identified
  attempts, immutable copies, independent REQUEST/TRANSIT/CONTACT/RETENTION
  events, no fake future window. CONTACT/SUCCESS can be followed by actual
  CATCH_OVERLOAD/GRIP_SLIP; that does not erase the successful physical contact.
- `climbing_controller.gd`: observational hooks and optional compact telemetry;
  actual old rejection/state branches remain the authority. Diagnostics OFF is
  the default, and collection is restricted to independent-aim profile3.
- `grip_up_lab.gd`: explicit diagnostics flag, separate per-session attempt JSONL with
  session/scene/policy/route identifiers, compact sampled traces, actual range
  hints, overlay, route access, optional precision/agency/recovery/readability
  ratings. UI ownership blocks experimental swing while entering ratings.
- `capture_debug_draw.gd`: three actual shoulder-sphere great circles, existing
  finite hand path and force vectors. Drawing does not add collision or forces.
- `transfer_test_level.gd`, two new scenes, `transfer_route_progress.gd`:
  configurable flat-wall reference route and a separate swing-required route.
  Markers are paint, not grip sockets. The score requires real anatomical hand
  contact followed by release of the old support; it never attaches hands.
- Tests/native harnesses, regression integration and evidence archives.

## Checks and limitations

Physical diagnostics suite:54checks at each60/120Hz; actual geometric, obstacle,
transit timeout, moving target, contact, overload, slip and support invalidation
cases, moment/reaction/work diagnostics and flag equivalence. OFF/OFF,ON/ON and
OFF/ON fixture trajectories/velocities/spin/forces/torques/targets/states agree
exactly in the recorded comparison. This does not imply zero CPU cost.

App route suite:14checks at each frequency, including10transfers at each spacing
and a real outside-static-reach diagnosis in the separate swing fixture.
Native Godot MCP Pro records the same input-driven route and a deliberate pose
rejection, plus diagnostic screenshots and real viewport footage. New code
loads without editor warnings/errors after correcting nullable-vector diagnostics.
Final regression:2148 checks,zero failures. Native:3/3 checks per60/120Hz.
Reports,screenshots,attemptJSONL and an automated native video are in v05_m1/.

No human has yet demonstrated or rated the new ten-transfer scene. Automation
proves a route can be completed under explicit timing; it does not establish
comfortable, understandable or skillful human control. P1/P2 remain a subsequent
measured study, not an assumed remedy. Work/energy are estimates for the body
relative to weighted supports; they exclude gravity/contact/joint/drag work and
support kinetic energy. See V05_M1_PHYSICS.md for the authority audit and fields.

Logging uses user://transfer_sessions/<UTC>_<PID>_<ticks>.jsonl to avoid concurrent test processes corrupting a shared append file. Each route test parses its own full log; earlier shared-file QA iterations were not used as final attempt evidence.
